# 0001. Record architecture decisions as ADRs

- Status: Accepted
- Date: 2026-10-30

## Context

The design doc ([design.md](../design.md)) describes what citefield is. It doesn't keep the reasons behind each choice, the alternatives that lost, or when a choice changed. Once a decision is edited in place, its history is gone. That history matters for an open-source library whose output format and signal contract are public API.

## Considered options

- **Design doc only**: one place to read, but rationale gets rewritten or dropped as the design evolves.
- **Nygard-style ADRs** (Context, Decision, Consequences): minimal, but has no slot for the options we rejected.
- **MADR-lite ADRs** (Context, Considered options, Decision, Consequences): a little more structure, and it keeps the comparison of options, which the design doc already does for parsers and licenses.

## Decision

We will record architecture decisions as MADR-lite ADRs in `docs/adr/`, numbered `NNNN-kebab-title.md`, from [template.md](template.md).

- `design.md` stays the description of the current design and links to the ADRs behind it.
- ADRs are append-only. To change a decision, write a new ADR that supersedes the old one; the old one only gets its status and a `Superseded by` line updated.
- The index in [README.md](README.md) is generated by `scripts/check_docs.py --write`, and `scripts/check_docs.py` checks numbering, the index, supersede links and relative links.

## Consequences

- Decisions that predate this ADR (0002–0010) are backfilled from `design.md` v1.0.0. Their rationale is limited to what the design doc states.
- Changing a public contract, a default dependency or the v1 scope now means writing an ADR, not only editing `design.md`.
- The `adr` and `docs-maintenance` Claude Code skills in `.claude/skills/` describe the workflow, so it is followed the same way by people and agents.
